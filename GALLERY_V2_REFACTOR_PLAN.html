0 · Executive summary

Your three goals map to four workstreams. The order matters: storage + DB first, UI second — the UI can only be fast and simple once every image source lives in one indexed store.

Your goalWorkstreamCore ideaPhase
1) Fewer loose files; keep only generated image + compressed preview; bundle if needed Storage overhaul One original PNG stays where it is. Thumbs + previews move into a single bundle store (SQLite blob file; pack-shard scale path). Endorsed copies become hardlinks (0 B). Sidecar .txt/.json files are absorbed into the DB and orphaned ones swept. → −82% files, −10.4 GB. Media policy: active = thumb+preview · archived = thumb only (auto-trash after 24 h) · trash = no media, metadata only. P1–P2
2) Extendable DB for all image sources (txt2img, img2img, inpaint, composition, qwen, krea2, …) Extensible database One items table + a sources registry + meta_json for per-source extras + tag categories (rating = composite single-select, workflow = independent multi, captions = auto). Adding a new engine = 1 registry row + 1 parser; a new tag category = 1 DB row. P1–P3
3) Gallery UI: advanced filters, speed, more actions Query API + UI v2 DB-only queries (no disk scans), batched lookups, FTS5 search, 7 core filter dimensions + extras, 4 sort keys, saved views; incremental card updates, ETag blob serving; batch actions, find-similar, compare, export. P4–P5
Safety Compatibility facade endorsement_db.py keeps its public API but delegates to the new store, with a dual-write window and a feature flag. Desktop Gallery + SD Lite keep working untouched during migration; rollback = flip one flag. P3
No new dependencies. Everything uses Python stdlib (sqlite3 incl. FTS5/JSON, zlib, os.link) — no pip installs, no new services. Migration runs online (webui keeps serving); the only restart needed is the usual one for new JS files.

2 · Target architecture

Three principles: ① one authoritative metadata DB (gallery.db) where every image source is just a provider row; ② derived data (thumbs, previews) lives in a separate, regenerable bundle store; ③ all consumers (desktop tab, SD Lite, scripts) talk to one Gallery API — the old endorsement_db API keeps working as a facade until everyone is migrated.

3.4 Edge cases handled

  • Cross-volume endorse link → fallback to copy + warning in log (same as today's semantics).
  • Blob store corruption → it is derived: rebuild from originals in the background; DB stays intact (separate file). Health check runs PRAGMA integrity_check at startup (cheap) and every N days.
  • Preview format upgrades (e.g. AVIF later) → new blob_ref.format; old blobs regenerated lazily per item; no migration file churn.
  • Moved originals → identity is uid/item id, not path; blobs keep serving after a move; the row's path updates on next scan.
  • Lifecycle media rules → archive keeps only a thumb (preview deleted; original file untouched, 24 h TTL with migration grace); Trash keeps no media at all (original files + blobs deleted, metadata retained); blob rows are removed on state change (SQLite) or dropped records are reclaimed by compaction (packs).
  • Endorsed protection → the TTL sweeper skips any item with rating = endorsed; un-endorse first if you really want it to expire. (Prevents “delete archived” sweeps from eating keepers.)

4 · Extensible database (goal 2)

4.1 Extensibility model

Sources registrysources(id, label, parser, schema_version, config_json) — seeded with txt2img, img2img, inpaint, composition, image_maker, qwen, krea2, removebg, nano_banana, comic_maker. The UI builds filter chips from this table — no code change to show a new source.
Parser registrynamed parsers: a1111 (PNG chunk/txt infotext), sidecar_txt, sidecar_json, none. A source picks one or supplies a tiny function.
Promoted columnsOnly fields with a real filter / sort / route role are columns: time, source, state, resolution (W/H), prompt, negative prompt (+ identity/routing: uid, path, size, sha256). Everything else — seed, sampler, schedule, steps, CFG, denoise, model(+hash), LoRA list, hires block, mask block, engine params — is compacted into meta_json (per-source schema_version). Promotion later = one generated column + index migration.
Tag categoriesTags live in categories with a cardinality rule: rating = single-select composite tag (endorsed | disliked), workflow = independent multi-select user tags, captions = automatic DeepDanbooru (scored). More categories (quality, character, …) are DB rows — no code change.
Kind columnkind = image | video | audio | doc — future AnimateDiff/Wan outputs slot in without schema surgery.
Variantsparent_id + variant link derived artifacts (removebg, upscales) to their source image — one tree per generation.

4.2 Schema sketch

-- gallery.db  (authoritative · keep in backup)
CREATE TABLE sources(
  id TEXT PRIMARY KEY, label TEXT, parser TEXT,
  schema_version INTEGER DEFAULT 1, config_json TEXT, created_at TEXT);

CREATE TABLE items(
  id INTEGER PRIMARY KEY, uid TEXT UNIQUE NOT NULL,        -- source:lower(relpath)
  source TEXT NOT NULL REFERENCES sources(id), kind TEXT DEFAULT 'image',
  path TEXT, rel_path TEXT,
  mtime REAL, file_size INTEGER,
  width INTEGER, height INTEGER,                           -- resolution filter/sort
  state TEXT DEFAULT 'active',                             -- active|staged|archived|trashed
  archive_expires_at REAL,                                 -- TTL: archived -> trashed (24 h)
  parent_id INTEGER REFERENCES items(id), variant TEXT,    -- removebg / upscale / …
  prompt TEXT, negative_prompt TEXT, infotext TEXT,        -- filter + display + FTS content
  meta_json TEXT DEFAULT '{}',                             -- seed/sampler/steps/model/… (JSON)
  sha256 TEXT,                                             -- lazy: dedupe / verify
  indexed_at TEXT, updated_at TEXT);
CREATE INDEX idx_items_source ON items(source);
CREATE INDEX idx_items_state  ON items(state, archive_expires_at);
CREATE INDEX idx_items_mtime  ON items(mtime DESC);
CREATE INDEX idx_items_size   ON items(width, height);

-- tags: categories define behaviour (cardinality + kind)
CREATE TABLE tag_categories(
  id TEXT PRIMARY KEY,                      -- rating | workflow | captions | …
  name TEXT, cardinality TEXT,              -- 'single' | 'multi'
  kind TEXT,                                -- rating | user | caption | system
  color TEXT, sort_order INTEGER DEFAULT 0);
CREATE TABLE tags(
  id INTEGER PRIMARY KEY, category_id TEXT REFERENCES tag_categories(id),
  name TEXT NOT NULL, color TEXT, created_at TEXT,
  UNIQUE(category_id, name COLLATE NOCASE));
CREATE TABLE item_tags(
  item_id INTEGER REFERENCES items(id) ON DELETE CASCADE,
  tag_id INTEGER REFERENCES tags(id),
  category_id TEXT, single INTEGER DEFAULT 0, -- denormalised for the index below
  source TEXT DEFAULT 'user',                 -- user | deepbooru | system
  score REAL, tagged_at TEXT,
  PRIMARY KEY(item_id, tag_id, source));
CREATE UNIQUE INDEX idx_one_single_per_category
  ON item_tags(item_id, category_id) WHERE single = 1;  -- composite tags: at most 1 per category

CREATE TABLE state_events(id INTEGER PRIMARY KEY, item_id INTEGER,
  event TEXT, at TEXT, payload_json TEXT);     -- lifecycle history (undo-friendly)
CREATE TABLE composer_states(item_id INTEGER PRIMARY KEY, blob BLOB, -- zlib JSON
  schema_version INTEGER, updated_at TEXT);
CREATE TABLE saved_views(id INTEGER PRIMARY KEY, name TEXT UNIQUE,
  filter_json TEXT, sort_json TEXT, created_at TEXT);
CREATE TABLE legacy_keys(legacy_key TEXT PRIMARY KEY, item_id INTEGER); -- transition only
CREATE VIRTUAL TABLE items_fts USING fts5(
  prompt, negative_prompt, infotext, tags_text,
  content='items', content_rowid='id');         -- phrase + column-scoped search

-- cache/gallery_blobs.db  (derived · regenerable · backup optional)
CREATE TABLE blobs(id INTEGER PRIMARY KEY, item_id INTEGER,
  kind TEXT,                 -- thumb | preview | net_variant  (never for trashed)
  format TEXT, width INTEGER, height INTEGER, size INTEGER,
  crc32 INTEGER, data BLOB, created_at TEXT);
CREATE INDEX idx_blobs_item ON blobs(item_id, kind);

4.3 Field ledger — what actually gets stored

Promotion rule: a field becomes a column only if a filter, sort, or route uses it. Everything else is compacted into meta_json. This keeps the table narrow and the schema stable while sources multiply.

If a meta field ever earns a filter (e.g. “model”), the upgrade is one migration adding a generated column + index — ALTER TABLE items ADD COLUMN model TEXT GENERATED ALWAYS AS (json_extract(meta_json,'$.model')) VIRTUAL — no data rewrite.

Modules introduced: gallery_db.py (schema + CRUD + FTS sync) · gallery_blobs.py (BlobStore) · gallery_sources.py (providers/parsers) · gallery_lifecycle.py (state machine + archive TTL sweeper) · gallery_query.py (FilterSet/SortSpec → SQL) · gallery_api.py (HTTP endpoints).

4.4 Identity, keys and compatibility

  • uid = source + ':' + lower(rel_path without extension) — deterministic, matches the existing qwen/krea2 shared-key scheme, so SD Lite archive state stays consistent. Collisions get a #2 suffix (rare: same-stem regenerations).
  • legacy_keys maps every old item_key (filename stem + engine-prefixed keys) to the new item id — old links, SD Lite probes and trash rows keep resolving during and after migration. Dropped in P6.
  • sha256 backfilled lazily in the background (≈12 GB to hash once); enables dedupe ("is this the same image?"), endorsed-link verification and corruption checks.
  • Facade: endorsement_db.py keeps every public function (endorse, search_generated, trash_archived_and_disliked, read_sidecar_metadata, …) but delegates to gallery_db.py. Dual-write to both DBs until gate G3 so rollback is a flag flip.
