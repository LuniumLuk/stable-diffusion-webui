2 · What the model is

  • Architecture: single-stream DiT, 32 layers, 7B parameters; block-causal attention (text token-level causal, image chunks bidirectional); flow matching with Euler discrete scheduling + dynamic shifting.
  • Text encoder: Qwen3-VL-8B — encodes both text instructions and condition images into one representation. (Editing requires the vision part — mmproj weights in GGUF terms.)
  • VAE: 64-channel RGBA autoencoder, 16× spatial compression → native transparency support.
  • One model, both jobs: text-to-image generation and instruction-based editing share the same weights; no checkpoint swap.
  • Editing powers: up to 10 reference images, local edits via circles / painted marks / separate masks, identity + product fidelity, outpainting, panorama / storyboard / infographic tasks.
  • Prefix KV cache: reference images + instruction are encoded once at step 1 and cached for all denoising steps — this is why editing with several refs stays fast.

3 · Prompting (text-to-image)

Qwen publishes two official “prompt enhancer” (PE) models (Qwen-Image-2.1-PE-T2I, Qwen-Image-2.1-PE-I2I) whose system prompts spell out exactly what the image model wants. The rules below are distilled from those prompts — you can follow them by hand.

The shape of a good prompt (official structure)

  1. Opening sentence (~20 words): medium + style + subject + background/palette, and usually orientation. 
    The image is a vertical realistic photograph of a samurai walking a rainy
old-town street at dusk, lantern light on wet stone, deep blue and amber palette.
  2. Background/surface next — not at the end. What the scene sits on, how far it falls off.
  3. Walk the frame in order — for scenes with several regions: top band → left, centre, right → bottom band. For one dominant subject: background → pose/placement → head/face → body & garments → what it holds → edge details. Roughly a third of sentences should start with a positional phrase (“On the right side of the frame, …”).
  4. Use 8–14 positional phrases (“upper-left”, “across the top”, “lower third”, “behind the left shoulder”) — they must reach corners, edges and centre.
  5. Lighting gets its own sentence — source, direction, quality, and the shadows/highlights it leaves.
  6. Close with ONE summary sentence: “The overall composition / mood / palette …” covering balance, palette, style, mood. Exactly one.

✔ Do

  • Write in English (description prose), present tense, third person, declarative — like an observer describing a picture you are looking at.
  • Name materials (brushed metal, coarse linen, weathered wood) and colours with modifiers (deep navy, muted olive) — almost never bare colours.
  • Enumerate, never summarise: “three paper lanterns”, not “some decorations”.
  • For people: posture, gaze, expression, hair, skin tone, each garment + colour/material. Age as life stage (“young adult”), never a number.
  • Objects by class (“a silver laptop”), brands only if you mean that brand.
  • Aim ~15–25 sentences / 300–500 words. A short brief should become a full description — density is the point.
  • Hedge what is genuinely ambiguous (“a notebook or a tablet”) — the model reads it as plausible variety.

✘ Don’t

  • No quality boosters — “masterpiece, best quality, 8K, highly detailed, award-winning” do nothing (or hurt); the PE prompts explicitly ban them.
  • No instruction voice — “create”, “make sure”, “you should” — the prompt describes, it does not command.
  • No tag-soup comma lists (SD1.5/SDXL habits). Write sentences.
  • Don’t put resolution or ratios in the prompt text (“2K”, “16:9”) — target ratio belongs in the size fields, not the words.
  • Don’t leave the frame half-invented: name every element’s place; avoid “various”, “several”, “etc.”

Short prompt → full prompt (official rewriting example)

Input: a corgi playing guitar in the rain

Output shape: a single dense paragraph — opening line fixes medium/style/subject/palette; then the scene is walked region by region; the rain, puddles and reflections are physical (shadows away from the light, wet surfaces reflect); the lighting sentence names direction and quality; final sentence covers composition and mood.

The official rewriter also picks the ratio: 3:2 default for horizontal, 2:3 default for vertical; 1:1 for icons/emblems/album covers; 16:9 for cinematic/presentation; 9:16 for phone banners.

4 · Text inside images

  • The model renders typography well — short strings, headlines, signage, UI mock text all work.
  • Quote the literal text with straight double quotes: a bold black headline across the top reads "SUMMER SALE". Text in the output stays in its own script (Chinese stays Chinese).
  • Give weight, colour, case and relative size; describe a line break as “a second line”, not a real newline.
  • If text is not meant to be read (distant signage, fine print) call it “blurred / indistinct / too small to read” instead of inventing letters.
  • Charts/tables/dashboards: treat axis labels, legends and cell values as text too — write them out.
  • sd.cpp note: quoted strings are preserved verbatim in practice (our edit test changed a sign’s text successfully).

5 · Negative prompts

Default: leave the negative prompt empty.

  • The official PE models never emit a negative prompt — their output schema even keeps the field only for tool compatibility, always "".
  • ComfyUI’s official Qwen-Image-2.1 workflows run CFG = 1 (no classifier-free guidance), so the negative prompt does nothing there.
  • In setups that do run true CFG (stable-diffusion.cpp at --cfg-scale 6.0), a negative prompt technically acts — but the model was not tuned for one. If you must, keep it short and generic; don’t port SDXL negative tag essays.
  • What actually fixes most problems: a more precise positive description (spatial placement, lighting, materials) — see §3.

Qwen-Image-2.1 is trained for ~2K output. The official buckets (all divisible by 32):

  • “4K”, “8K” in a brief are quality descriptors, not sizes — render at 2K-class anyway.
  • Editing: default is to follow the input image’s aspect ratio (at ~1024–2048-class pixel budget). Request a different canvas only when composing a new scene; for outpainting widen/tallten the ratio by roughly the extended area (+30–50%).

Practical CFG guidance

  • Modern Qwen workflows trend to no CFG / guidance ≈ 1 because the model leans on its distilled guidance signal. ComfyUI ships exactly that.
  • stable-diffusion.cpp’s official Qwen-Image-2.1 example uses --cfg-scale 6.0 — verified here to give excellent results, so keep it for the local GGUF setup unless you experiment.
  • Higher steps mostly refine micro-detail/typography; 20 → 40 steps is roughly linear in time.

8 · Image editing

✔ Edit prompts

  • Write it as an instruction, leading with the operation: “Replace the background with…”, “Change the sky to…”.
  • Edit exactly one thing at full strength, and pin everything else with a blanket preservation clause: “keep the character, pose, facial identity and lighting unchanged”.
  • Describe appearance in detail only for what you are changing; for things you preserve, name them by type/position/role — over-describing preserved content makes it drift.
  • Multiple references: address them as <image1>, <image2> (slot order matters) and state each role: 
    Keep the character and pose in <image1> unchanged, put the light
blue denim shirt from <image2> on the character, preserve the
original facial features, hair, body shape and pose.
  • Text: commit to the exact characters in quotes; that is also how you edit existing text (“change the sign to read "qwen21"”).
  • Compose many references (up to 10) by naming the target canvas and the material sources: “These three characters are sitting around a campfire in a forest.”

✘ Avoid

  • Leakage: letting unrequested changes in (“clean up” defects nobody asked about).
  • Under-editing: a result a viewer could mistake for the input because the change was applied faintly.
  • Vague degree words without commitment — “slightly different lighting” → say what the light does.
  • Natural-language image references when several are supplied (“the first image”, “图1”) — use the <imageN> tags.
  • Describing a person’s identity in words when you have their photo — point at the reference instead.

Local edit techniques (official examples)

  • Circles: mark regions and reference the mark colours in the prompt: “Remove the metal watch in the blue circle, change the hair in the red circle to black, replace the area in the green circle with gray short-sleeved linen pajamas.”
  • Painted annotation: point at the marked area — “add a diver in the white marked area”.
  • Separate mask: pass original + mask as two inputs and describe the change; keeps the untouched pixels intact.
  • Background removal: instruction “Remove the background, and output a PNG image” (transparency needs the RGBA-capable stack — sd.cpp outputs RGBA PNGs).
  • Transparent generation from text — use the official wrapper: 
    This is an RGBA image with transparency. <your description>. The image
has alpha channel and the background is transparent.
  • Sequential editing: apply one local edit at a time, keeping the rest fixed — chained edits compose into simple animations/storyboards.

9 · This machine’s setup (stable-diffusion.cpp)

  • Models in use: DiT qwen-image-2.1-Q4_K_M.gguf (4.6 GB), text encoder Qwen3VL-8B-Instruct-Q4_K_M.gguf (5.0 GB), vision mmproj-Qwen3VL-8B-Instruct-F16.gguf (1.16 GB, editing), VAE qwen_image_2.1_vae_bf16.safetensors (676 MB).
  • Server: qwen_image_server.bat → web UI + A1111-compatible API on 127.0.0.1:7862; managed by the WebUI tab Qwen-Image 2.1 (Start/Stop/Restart).
  • Auto-save: every completed web-UI generation is archived as JPEG to outputs/qwen/<date>/<hh-mm-ss>/<n>.jpg (+ <n>.txt params sidecar) by the patched frontend + local receiver.
  • CLI: qwen_image_txt2img.bat "prompt" 1k:2:3 — presets 1k:1:1 / 1k:2:3 / 1k:3:2 / 2k:1:1 / 2k:2:3 / 2k:3:2; optional steps + seed after the preset.
  • Editing: add reference images in the web UI (or POST /sdapi/v1/img2img with init_images). First-step encoding with refs is cached (prefix KV) — repeated edits on the same refs are faster.
