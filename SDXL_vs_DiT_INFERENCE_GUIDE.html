Inference pipelines: SDXL vs DiT

A hands-on walkthrough of what actually runs between pressing Generate and getting pixels — the two architectures side by side, with the tensor shapes of the checkpoints that live in this repo, the sampler math, and interactive toys for the parts that are easier to feel than to read.

0 · The skeleton both share

You already know how to train a small network, so drop the "AI magic" framing. Inference for both families is one loop wrapped in two adapters: 

prompt ──► text encoder ──► conditioning   c            (runs ONCE per prompt)
                                  │
noise  x_T ~ N(0, I)              │
   │                              ▼
   └────────►  for t = T … 1:  x ← step( model(x, t, c), x, t )      ← runs N times
                                  │
                                  ▼
                          VAE decoder ──► RGB image

Everything that differs between SDXL and DiT lives in text encoder, model and step. The wrappers (tokenizer in, PNG out) are the same.

Three consequences you can already predict, and that the rest of the page makes concrete:

  • Text encoding is free, sampling is not. The prompt is encoded once; the model runs once per step per CFG pass. A 20-step CFG-4 job is 40 forward passes of a multi-billion-parameter network.
  • Resolution enters through the latent grid. Both families downscale by 8 per side, so a 1024×1024 image is a 128×128 latent. Cost then follows the number of latent cells — or, for a transformer, the number of tokens those cells become.
  • The model never sees pixels. It sees a tensor that the VAE can decode. That is why the VAE is quality-critical (anime line art is brutal on VAEs) and why its decode time is a real line item.
Vocabulary check "Latent diffusion" (SDXL) and "DiT" (SD3, Flux, Qwen-Image, Anima/Astra) are both latent models. The words describe the denoiser's architecture, not the pipeline: SDXL uses a convolutional UNet, DiT uses a plain transformer over image patches. Both are wrapped in the same text-in / VAE-out harness.

1 · SDXL: dual CLIP into a UNet

SDXL's denoiser is a 2.57 B-parameter UNet (measured: 1 680 tensors in the checkpoint this fork loads). It is a U-shaped stack of residual+attention blocks that keeps a full 2-D feature map at every scale, and it conditions on text through cross-attention inserted at several scales. Step through it:

Why two text encoders

SDXL concatenates the penultimate hidden states of CLIP ViT-L/14 (12 layers, width 768) and OpenCLIP ViT-bigG/14 (32 layers, width 1280) along the channel axis: 768 + 1280 = 2048. That 2048 is exactly the input width of every cross-attention k projection in the UNet — you can read it straight out of the weights (attn2.to_k.weight is [1280, 2048] at the deep levels and [640, 2048] at the 640-channel level).

The second signal CLIP provides is pooled: bigG's text_embeds, a single 1280-vector that summarises the whole prompt. It is added to the timestep embedding instead of being attended to, so it acts as a global style/length knob rather than per-token information.

measured in this repo's checkpoint time_embedding.linear_1.weight is [1280, 320] → the 320-dim sinusoidal timestep embedding is lifted to 1280. add_embedding.linear_1.weight is [1280, 2816], and 2816 = 1280 (timestep) + 6 × 256: the six time_ids numbers (original height/width, crop y/x, target height/width) each get a 256-dim Fourier expansion. That is how SDXL knows the requested resolution and crop — not through the text.

The cheapest-to-notice detail: the highest-resolution level is convolution only. Attention is quadratic in tokens, so 128² = 16 384 tokens would be four times the cost of the 64² level; SDXL simply does not put attention there. (Why SD 1.5 duplicated heads above 512² is a different story — that one is mostly about the training-resolution distribution, which is exactly what SDXL's 1024² multi-aspect bucketing fixed.)

The refiner (optional second stage)

SDXL base can hand its latents to a second, separate UNet — the refiner — trained on the last ~20 % of the noise schedule, i.e. only the low-noise part where texture and micro-detail are decided. It shares the text encoders and the VAE but drops cross-attention at its highest-resolution block: by then the composition is fixed and only local detail is left. Practically it is "hires-fix without the upscale", which is why it is usually skipped when you are going to upscale anyway.

2 · DiT: patches in, transformer out

A DiT throws away the U-shape, the convolutions and the multi-resolution feature maps. It turns the latent into a sequence of tokens and runs a plain transformer over them, exactly like a language model over words. The concrete numbers below are this repo's novaAnimeAM_v40 (Anima 2B, 28 blocks, 2.091 B parameters).

Patchify: the image becomes a sentence

The VAE gives a 16 × 128 × 128 latent for 1024×1024 (16 channels instead of SDXL's 4). A 2×2 patch taken across all channels is one token of 2 × 2 × 16 = 64 numbers, and a single linear layer maps it to the model width. A 1024² image therefore becomes 64 × 64 = 4 096 tokens of width 2048. Sequence length is pixels ÷ 256 — that single line explains almost every timing you will measure.

measured in this repo's checkpoint x_embedder.proj.1.weight is [2048, 68]. 68 = 2×2×17, so the patch is 2×2 over 17 planes — the Qwen/Wan VAE in models/Anima/vae is 16-channel (decoder.conv1.weight = [384, 16, 3, 3, 3]), so this checkpoint folds one extra plane into the patch embedding. Checkpoint-specific detail; the pattern (patch → linear → sequence) is universal.

adaLN: how time and text enter a token transformer

A transformer has no idea what "step 12 of 20" means, and attention alone cannot inject a global scale/shift. DiTs use adaptive layer norm: the conditioning vector predicts, per block and per sub-layer, a shift, a scale and a gate. Concretely, from the weights: adaln_modulation_self_attn, …_cross_attn and …_mlp are each [256, 2048] → SiLU → [6144, 256], and 6144 = 3 × 2048 — one shift/scale/gate triple per sub-layer.

Play with the transform itself:

normalised feature x̂ modulated: gate · ((1+scale)·x̂ + shift)
scale0.40
shift0.15
gate1.00

Set gate = 0: the block outputs nothing, i.e. it is the identity. That is the adaLN-Zero initialisation — every block starts as a no-op and is "switched on" during training, which is why these models train stably without warmup tricks.

What the conditioning actually is here

  • Text encoder: Qwen3-0.6B, a causal LLM — not CLIP. No 77-token window, no pooled vector; the token count is the real prompt length (plus a template), and the width is 1024.
  • How it enters: the DiT's cross_attn.k_proj / v_proj weights are [2048, 1024] — they read the 1024-wide LLM states directly, while q_proj is [2048, 2048] from the image tokens. So image tokens query, text tokens are the keys/values, at every one of the 28 blocks.
  • Self-attention: q/k/v/o are all 2048×2048 with q_norm/k_norm of size 128 → 16 heads × 128. QK-norm is the modern stabiliser (same idea as in ViT-22B / Chameleon): RMS/LayerNorm applied to q and k before the dot product.
  • MLP: 2048 → 8192 → 2048 (4× expansion). One block ≈ 12·d² ≈ 50 M parameters; 28 blocks ≈ 1.4 B, plus embeddings and the 2048-wide text adapter.
Joint vs cross attention. Some DiTs (SD3, Flux, Qwen-Image) concatenate image and text tokens into one sequence and let them attend to each other bidirectionally ("MMDiT" / joint attention); others (this Anima checkpoint) keep a separate cross-attention. The compute difference is minor — both are just attention over a longer key set — but it changes how strongly text can rewrite image tokens at every layer. Both variants share the patchify + adaLN skeleton above.

Flow shift, interactively

Flow matching samples σ on a straight line from 1 to 0, but the useful part of that line depends on resolution: a 1-megapixel image needs more of its steps in the high-noise region than a 0.1-megapixel one. The fix is a one-line remap applied to the schedule, not to the model: 

σ' = shift · σ / (1 + (shift − 1) · σ)        # shift = 1 → unchanged, shift = 3 → steps crowd the noisy end
shift1.0
steps20

Drag shift up and watch the markers slide toward σ≈1. The endpoints never move — only the distribution of steps along the path. sd.cpp exposes this as --flow-shift; A1111 exposes it for Anima as the Anima flow shift setting (leave it at 0 / auto unless you are chasing a specific look).

4 · CFG: the setting that doubles your bill

Classifier-free guidance evaluates the model twice per step — once with the prompt, once with the negative prompt — and extrapolates away from the unconditional prediction: 

v̂ = v_uncond + s · (v_cond − v_uncond)          # same formula for ε in SDXL, v in a DiT
                                            # s = 1 → the uncond pass is a no-op
                                            # s = 0 → pure unconditional (prompt ignored)

measured on this machine, 2B Anima DiT, 832×1216, 20 steps CFG 1.0 → 7.8 s sampling · CFG 4.0 → 15.5 s sampling. The ratio is 2.0, not 1.9 — because at s = 1 the unconditioned branch is skipped entirely and only one pass runs. Every published "20 steps" number you see is really "20 or 40 network evaluations" depending on CFG.

Two practical notes that fall out of the formula. First, s ≤ 1 makes the negative prompt mathematically irrelevant — it is multiplied by s − 1 ≤ 0. Second, nothing about CFG is architecture-specific: SDXL, DiT, UNet, transformer, all the same. It is applied to whatever the model predicts, before the sampler update.

5 · Where the seconds go

For a DiT the estimate is short enough to do in your head. Tokens are N = (W/16)·(H/16); a dense block costs 2·N·P_block FLOPs for its linears plus 4·N²·d for attention. So the attention share of one pass is: 

attn_share ≈ N² · 4d  /  (N² · 4d + N · 12d²)  =  N / (N + 6d)
   N = 1536 tokens (512×768)  → 11 %
   N = 4096 tokens (1024×1024) → 25 %        # d = 2048, 28 blocks

That is exactly the superlinearity the profiler found: with the slow attention path, the cost per megapixel grew ~27 % from 0.39 to 1.01 MPx; with flash attention it grows ~11 %.

Model: t = passes · steps · (0.33·MPx + 0.03·MPx²) + 1.15·MPx — fitted to the measurements in §7 on an RTX 5070 Ti with --diffusion-fa --vae-conv-direct. Spot checks: 832×1216 / 20 steps / CFG 4 → 16.0 s measured, 1024×1024 → 16.6 s, 512×768 → 5.6 s.

Why SDXL does not follow this law. Its 2.57 B parameters are not applied uniformly: the 320-channel blocks run on 128² grids while the 1280-channel blocks run on 16². Cost still grows with pixels, but the constant per pixel is dominated by convolutions at high resolution, not by attention over all tokens. A UNet at 512² therefore tends to be cheaper per pixel than a DiT at 512². The exact crossover depends on the GPU, but this is the real reason the 1-MP bucket is the sweet spot for DiTs: below it the transformer is under-utilised, above it the attention term starts compounding.

7 · How this fork runs both

Same UI, two very different code paths. The router is modules/backends/__init__.py: process_images() asks resolve(p) whether the selected checkpoint is a DiT model; if it is, the torch UNet/CLIP pipeline is never touched.

SDXL checkpoint

sd_models.load_model()
  → sd_hijack (CLIP-L + CLIP-G)
  → StableDiffusionProcessing
  → UNet.forward  ×steps ×cfg
  → VAE.decode

All in-process, torch. Memory is a single 6–8 GB lump you can watch shrink when you switch to a DiT model.

Anima / DiT checkpoint

backends.resolve(p) → runner.process_images_via_anima()
  → park the SD checkpoint on CPU
  → sd_cpp/sd-server.exe  (HTTP sidecar)
       --diffusion-model … --llm … --vae …
       --diffusion-fa --vae-conv-direct
  → POST /sdcpp/v1/img_gen  {prompt, w, h, seed,
        sample_params:{sample_method, sample_steps,
                       guidance:{txt_cfg}}}
  → poll /sdcpp/v1/jobs/<id> → b64 PNG

Out of process, in stable-diffusion.cpp's ggml/CUDA stack. A1111 keeps the prompts, seeds, infotext and file saving; it never builds conditioning.
