SD Lite — UX sketch (review draft)

Wireframes for the proposed Mobile Lite UI — a separate, mobile-first front-end served at /mlite/ that becomes the default entry for phones. Scope: Text (txt2img), Image (img2img + inpaint), Gallery, Compose. Companion document: MOBILE_LITE_PLAN.md (full plan, API, open questions).

How to read: each block below is a stylised phone screen. Boxes are not pixel mockups — they show layout, grouping and interactions. Numbered notes on the right explain what each part does and how it behaves.
Legend: button / chip primary action selected / active image / transparency dashed outline = input / empty state

  1. Top bar (46px) — brand, checkpoint chip (tap = searchable model sheet, switch applies server-side and persists), settings gear (Lite settings sheet).
  2. Content — exactly one screen is visible; only its content area scrolls. The page itself never scrolls, so dragging on a canvas/slider can't move the page.
  3. Job strip — appears only while generating (any screen): live preview thumbnail (tap = fullscreen), step counter, percent bar, ETA, Stop (= /interrupt). While visible, content gets extra bottom padding so nothing is hidden.
  4. Bottom nav (54px) — the four hot-path screens. No other tabs: everything else stays in the desktop UI.
  5. Feedback — toasts above the tab bar for every async result (ok / warn / error); a translucent busy overlay for actions > 150 ms (image load, save, SAM, model switch).
  6. Sheets — secondary controls slide up from the bottom (max 82 % height). One at a time; ✕ or backdrop tap closes. Nothing modal blocks a generation.

  1. Mode switch — Image = plain img2img; Inpaint = mask editor + mask sent with the request. Switching keeps the loaded image.
  2. Source image — Upload / Camera (rear) / Gallery picker, or drag&drop on desktop. Loaded at ≤ 2048 px so huge photos don't stall the bridge. The little ✕ clears it.
  3. Mask editor (inpaint only) — draw directly on the image; white = region to regenerate (matches A1111 semantics). Tools: paint, erase, ✨ SAM tap, undo (vector replay — cheap memory), clear, brush size slider.
  4. SAM tap — tap an object → 3 candidate masks from the Segment Anything extension; the 1 / 2 / 3 buttons choose which candidate the next taps use, and re-tapping the same spot replaces its selection. Status toast shows the round-trip time.
  5. Prompt card — same editor as Text, but a separate draft so inpaint experiments don't clobber the txt2img prompt.
  6. Params summary — includes denoise (the key img2img control). The sheet adds mask blur, output size (match input default / custom W×H) and input fit (stretch / crop&resize).
  7. Generate — blocked with a toast if the mask is empty (inpaint), then behaves exactly like Text (job strip, results, recovery).

9 · States to design for (checklist)

Empty

  • No checkpoint list / server unreachable → boot error screen + Retry
  • No source image → Image screen empty state
  • No mask → Generate blocked with toast
  • No layers → Compose empty canvas + hint
  • Empty gallery views → “nothing here yet / no matches”

Busy / feedback

  • Job strip: queued → running (live preview) → done (toast with count + time)
  • Busy overlay: image load, SAM, save, model switch
  • Recovery toast when a response was lost but the result was recovered
  • Errors always include the server's message, never a bare “failed”

10 · Out of scope for v1 (deliberately)

Extras / PNG Info / Settings / Queue / training / ControlNet panels / LoRA browser / local-LLM / Qwen tabs, hires fix & refiner, styles dropdown, desktop composer's paint & colour-replace tools. The Gradio UI stays available for those — the lite app is additive, and the desktop experience is not modified.

Review next: the ten open questions are listed in MOBILE_LITE_PLAN.md § 11 — the ones that shape the most code are: composer scope (transforms now, paint later?), hires in v1, Lora quick-insert, gallery view subset, and the redirect detection strategy.
